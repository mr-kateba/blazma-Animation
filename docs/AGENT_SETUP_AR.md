# ربط Claude Code وCodex بـ Blazma Animation

هذا الدليل يشرح كيف تجعل الذكاء الاصطناعي يحرّك شخصيتك داخل البرنامج. لا تحتاج إلى برمجة.

## ماذا يوجد في الحزمة

بعد فك ضغط البرنامج ستجد مجلد `tools` فيه ملفان:

| الملف | ما هو |
|---|---|
| `blazma-mcp.exe` | خادم MCP: هو الذي يتصل به Claude Code (وأي برنامج يدعم MCP). |
| `blazma-anim.exe` | أداة سطر الأوامر: يستعملها Codex أو أي وكيل يشغّل أوامر في الطرفية. |

كلاهما يعمل بدون تثبيت .NET.

## 1. Claude Code

1. فك ضغط البرنامج في مكان ثابت، مثلاً `C:\Blazma`.
2. افتح الطرفية (PowerShell) وشغّل:

```
claude mcp add blazma -- "C:\Blazma\tools\blazma-mcp.exe"
```

3. شغّل `claude` ثم اكتب `/mcp` وتأكد أن `blazma` يظهر باللون الأخضر (connected).
4. اطلب مثلاً: «أنشئ مشروعاً جديداً في `C:\anim\demo.blazanim` وأنشئ حركة مشي قصيرة للشخصية».

**هل يجب فتح البرنامج؟** لا.

- **البرنامج مفتوح:** الخادم يتصل به تلقائياً، فترى التغييرات مباشرة في النافذة وتوافق عليها أو ترفضها.
- **البرنامج مغلق:** يعمل الخادم وحده (وضع Headless): ينشئ المشروع ويعدّله ويحفظه كملف. افتح الملف لاحقاً في البرنامج.

لإجبار وضع معيّن أضف `--headless` (بدون البرنامج) أو `--attach` (مع البرنامج فقط) بعد اسم الملف.

لمن يستعمل ملف الإعداد `.mcp.json` في مجلد المشروع:

```json
{
  "mcpServers": {
    "blazma": { "command": "C:\\Blazma\\tools\\blazma-mcp.exe", "args": [] }
  }
}
```

## 2. Codex (أو أي وكيل يستعمل الطرفية)

Codex يستطيع تشغيل الأوامر، فيكفي أن تقول له أين الأداة. أمثلة:

```
C:\Blazma\tools\blazma-anim.exe commands
C:\Blazma\tools\blazma-anim.exe new C:\anim\demo.blazanim --name Demo
C:\Blazma\tools\blazma-anim.exe inspect C:\anim\demo.blazanim --json
C:\Blazma\tools\blazma-anim.exe run C:\anim\demo.blazanim walk.jsonl
```

- الأمر `commands` يعرض كل ما يمكن عمله.
- الأمر `run` ينفّذ ملف سكربت (سطر لكل أمر) كمهمة واحدة. إذا فشل أي سطر يتوقف ولا يحفظ شيئاً.
- أضف `--attach` (بدون اسم الملف) ليعمل على البرنامج المفتوح بدل الملف.
- أخبر Codex أن يقرأ `docs/AI_GUIDE.md` و`docs/AGENT_RECIPES.md`: فيهما الاصطلاحات (الوحدات والمحاور) ووصفات جاهزة.

يمكنك أيضاً إضافة `blazma-mcp.exe` إلى Codex كخادم MCP (في ملف إعداد Codex `config.toml`):

```toml
[mcp_servers.blazma]
command = "C:\\Blazma\\tools\\blazma-mcp.exe"
```

## 3. الوضعان: Assisted وAutonomous

تغيّر الوضع من لوحة **AI Workspace** داخل البرنامج.

| | Assisted (المساعَد، الافتراضي) | Autonomous (المستقل) |
|---|---|---|
| تعديلات الوكيل | تُطبَّق فوراً لتراها، لكنها تُجمَّع في **مهمة** تنتظر قرارك | تُطبَّق وتُقبل تلقائياً عند انتهاء المهمة |
| قراراتك | **Approve** يُبقي التغييرات، **Reject** يتراجع عن المهمة كلها | تستطيع دائماً التراجع بـ Undo |
| الحذف | يطلب موافقتك دائماً | يطلب موافقتك دائماً |

ابدأ بـ Assisted حتى تتعود على عمل الوكيل.

## 4. قواعد الأمان

- **الحذف يحتاج موافقتك دائماً** (حذف مقطع أو شخصية أو وضعية) عندما يكون البرنامج مفتوحاً. يظهر الطلب في AI Workspace؛ الوكيل لا يستطيع الموافقة بنفسه.
- **لا يستطيع الوكيل تشغيل أوامر على جهازك** ولا قراءة ملفات عشوائية. الأدوات تلمس ملفات المشروع فقط، واستيراد شخصية (`rig_import`) من خارج مجلد المشروع يحتاج موافقتك.
- **التراجع (Undo):** الوكيل لا يتراجع إلا عن تعديلاته هو، ولا يمسّ عملك أنت. وعند رفض مهمة بعد أن عدّلت أنت شيئاً فوقها، يرفض البرنامج التراجع حتى لا يضيع عملك.
- **لا يوجد اتصال بالشبكة:** الخادم يتحدث مع البرنامج عبر قناة محلية مخصصة لمستخدم ويندوز الحالي فقط.
- **قفل الملف:** لا يمكن فتح المشروع نفسه من برنامجين في وقت واحد (البرنامج والوكيل مثلاً). تظهر رسالة `project_locked`؛ أغلق أحدهما.
- **النسخ الاحتياطي:** يُحفظ الملف بشكل آمن (كتابة ثم استبدال) ويُحتفظ بنسخة سابقة بجانبه. في وضع Headless **لا توجد موافقات** لأن الشخص الذي شغّل الوكيل هو من طلب العمل، فاستعمله على نسخ تجريبية أولاً.
- الوكيل في وضع Headless لا يستبدل مشروعاً به تغييرات غير محفوظة إلا بإذن صريح (`discard`)، ولا ينشئ مشروعاً فوق ملف موجود.

## 5. حل المشكلات

| المشكلة | الحل |
|---|---|
| `/mcp` يعرض failed | تأكد من المسار في أمر `claude mcp add`، وأن الملف غير محجوب (انقر بزر الفأرة اليمنى على الملف ← Properties ← Unblock). قد يظهر تحذير SmartScreen أول مرة. |
| الوكيل لا يرى النافذة المفتوحة | شغّل البرنامج قبل بدء `claude`، أو أعد تشغيل الجلسة (الاتصال يتم عند البدء). |
| `project_locked` | المشروع مفتوح في برنامج آخر. أغلقه أو اعمل على نسخة. |
| `approval_required` | وافق على الطلب في AI Workspace ثم اطلب من الوكيل المتابعة. |

مراجع للوكيل: `docs/AI_GUIDE.md` (المفاهيم) و`docs/AGENT_RECIPES.md` (وصفات) و`docs/MCP_TOOLS.md` وCLI_REFERENCE.md (القوائم الكاملة، مولّدة تلقائياً).

## قواعد الأمان (مهمة)

- **الحفظ:** الوكيل يحفظ فقط في ملف المشروع المفتوح، أو في ملف `.blazanim` **جديد**. لا يستطيع أبدًا الكتابة فوق أي ملف موجود آخر.
- **قراءة الملفات (استيراد الشخصيات):** مسموحة فقط من مجلد المشروع، ومن المجلد الذي شُغّلت منه الأداة، ومن المجلدات التي تسمح بها أنت:
  - داخل البرنامج: لوحة الذكاء الاصطناعي ← "المجلدات المسموح بقراءتها".
  - بدون البرنامج: أضف `--allow-read "C:\Models"` إلى أمر `blazma-mcp`، أو ضع المجلدات في متغير البيئة `BLAZMA_ALLOW_READ`.
- **مسارات الشبكة والأجهزة** (مثل `\\server\share`) مرفوضة دائمًا.
- **الحذف:** داخل البرنامج ينتظر موافقتك دائمًا، حتى في الوضع المستقل.
- **الوكيل لا يستطيع التراجع عن تعديلاتك** أنت، ولا تشغيل أوامر النظام.
