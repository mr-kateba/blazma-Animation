# صيغة البيانات — `.blazanim`

> رقم المخطط الحالي: `schemaVersion: 5` (المرحلة 9). الملفات بالإصدارات 1 إلى 4 تُفتح وتُرقّى تلقائيًا، وهذا مُختبَر بملفات حقيقية في `tests/fixtures/schema-v1/` حتى `schema-v4/`.

## 1. الحاوية

ملف `.blazanim` هو أرشيف ZIP (الضغط: Deflate للـJSON، وStore للملفات المضغوطة أصلًا مثل PNG/GLB):

```
project.json          البيانات الوصفية، رقم المخطط، الفهارس
scenes/main.json      المشهد: الشخصيات ووضعياتها الحالية
rigs/<id>.json        الهياكل العظمية، مقابض IK، سلاسل IK، خرائط العظام
poses/<id>.json       مكتبة الوضعيات
clips/<id>.json       مقاطع الأنيميشن
sequences/<id>.json   تسلسلات المقاطع (Blending/انتقالات) — المخطط 4، §8
props/<id>.json       الأجسام القابلة للتحريك (Props) — المخطط 4، §9
templates/<id>.json   مكتبة قوالب المقاطع في المشروع — المخطط 4، §10
combos/<id>.json      سلاسل الضربات (Combos) — المخطط 5، §11
assets/<id>/<file>    ملفات مستوردة مضمّنة داخل المشروع (GLB)، فيبقى المشروع كاملًا حتى لو حُذف الملف الأصلي
metadata/ai/<id>.json   Prompt وSeed وإعدادات التوليد لكل مسودة AI
(سجل العمليات oplog.jsonl يبقى في مجلد الجلسة ولا يُضمَّن إلا باختيار المستخدم)
previews/             صور مصغّرة
```

**لماذا ZIP وليس مجلدًا؟** ملف واحد أسهل للمستخدم في النقل والمشاركة. أثناء العمل يُفك المشروع إلى مجلد جلسة،
والحفظ يعيد بناء الأرشيف.

## 2. الحفظ الذري والاستعادة

1. كتابة الأرشيف إلى ملف مؤقت جديد باسم عشوائي قصير `.blz-<random>.tmp` في المجلد نفسه (القرص نفسه، شرط للاستبدال الذري). يُنشأ الملف حصريًا (`FileMode.CreateNew`، أي `O_EXCL`): لا يُتبع رابط رمزي مزروع بهذا الاسم ولا يُقتطع ملف موجود. نسخة `.bak` تُكتب أيضًا إلى ملف مؤقت جديد ثم تُنقل بـ`rename` فوق `.bak` (فلا يُتبع رابط باسمها).
   - وضع **بلا استبدال** (`overwrite: false`، يستخدمه التصدير عندما لا يُطلب الاستبدال): النقل الأخير `File.Move(temp, path, overwrite: false)` يفشل ذريًا إن ظهر الملف الهدف أثناء الكتابة (`file_exists`)، ويُحذف الملف المؤقت.
2. `fsync`، ثم التحقق من الأرشيف بإعادة قراءته ومطابقة checksums: ‏SHA-256 لكل ملف مسجلة في `project.json`. `project.json` نفسه لا يدخل في هذه القائمة، ويُتحقق منه بتحليل JSON وفحص المخطط.
3. الاستبدال الذري:
   - **Windows:** `File.Replace` مع نسخة `.bak`. في **الحفظ الأول** لا يوجد ملف هدف، فنستخدم `File.Move`. عند خطأ مشاركة مؤقت (مضاد فيروسات، مُفهرِس) نعيد المحاولة مع تأخير متزايد.
   - **Linux:** إنشاء `.bak` بـhard link (أو نسخ)، ثم `rename`، ثم `fsync` للمجلد.
4. **ملف القفل** `.lock`: يحتوي على PID واسم الجهاز ووقت البدء، مع قفل نظام التشغيل (`FileShare.None`). القفل القديم بعد انهيار يُكتشف ويُزال بأمان.
5. **الحفظ التلقائي:** كل N دقائق (قابل للضبط، الافتراضي 3) إلى مجلد الاستعادة في بيانات المستخدم المحلية، وليس فوق ملف المستخدم.
   - يستخدم مسار tmp+rename نفسه، مع جيلين متناوبين على الأقل، فلا يُفقد كل شيء إذا انقطع الحفظ في منتصفه.
   - تُؤخذ اللقطة على الخيط الرئيسي، والضغط والكتابة على خيط خلفي.
6. **الاستعادة بعد الانهيار:** عند فتح المشروع تُكتب علامة "جلسة مفتوحة"، وتُحذف عند الإغلاق السليم. عند الإقلاع، إذا وُجدت العلامة مع autosave أحدث من الملف الأصلي، يُعرض على المستخدم الاستعادة أو التجاهل.

## 5. مقطع الأنيميشن (Clip)

```json
{
  "id": "01J...",
  "name": "Walk",
  "fps": { "num": 30, "den": 1 },
  "duration": 705600000,
  "skeleton": "01J...",
  "loop": { "enabled": true, "start": 0, "end": 705600000 },
  "rootMotion": { "mode": "extract", "bone": "root", "axes": "xz+yaw" },
  "tracks": [
    {
      "id": "01J...",
      "target": { "kind": "bone", "id": "01J..." },
      "channel": "rotation",
      "keys": [
        { "t": 0, "v": [0, 0, 0, 1], "interp": "cubic",
          "inTan": [0,0,0,0], "outTan": [0,0,0,0] }
      ],
      "locked": false, "group": "Legs"
    }
  ],
  "events": [ { "id": "01J...", "time": 352800000, "name": "foot_contact_l", "kind": "Footstep", "data": { "surface": "stone" } } ],
  "combat": { "phases": {...}, "hitboxes": [...] },
  "constraints": [],
  "metadata": { "source": "manual" }
}
```

- `channel`: `translation` (‏3 قيم، متر) أو `rotation` (‏4 قيم، Quaternion xyzw) أو `scale` (‏3 قيم) أو `custom:<name>` (قيمة واحدة).
- كل المراجع بين الكائنات بـ`id` مجرد (ULID) وليس بالاسم، فإعادة تسمية عظمة لا تكسر أي مقطع. الأسماء تُستخدم فقط عند الاستيراد ومطابقة الهياكل.
- `target.kind`: `Bone`، أو `Control` (أهداف IK وPole، ولها تعريف في الـRig)، أو `Prop` (المخطط 4: جسم من §9؛ القنوات `translation`/`rotation`/`scale` لإزاحته عن العظمة إن كان مربوطًا وإلا لتحويله العالمي)، و`Object` محجوز ولا يُكتب. (تُكتب القيم بحرف كبير أول كما في الملفات الحقيقية.)
- `interp`: `step` أو `linear` أو `cubic`.
  - `linear` للدوران = Slerp.
  - `cubic` = **Hermite متوافق مع glTF CUBICSPLINE**: `inTan`/`outTan` مشتقات بوحدة "قيمة لكل ثانية"، لكل مكوّن على حدة، والدوران يُطبَّع بعد الحساب. بهذا يكون التصدير إلى glTF دون فقدان.
  - أدوات محرر المنحنيات الإضافية (مثل Bezier الموزون) تبقى داخل المحرر، وعند التصدير تُعاد عيّنتها (resample) بحد خطأ محدد.
- قنوات `custom:<name>` تُصدَّر في JSON sidecar، أو عبر امتداد `KHR_animation_pointer` عندما يدعمه الهدف.
- **الأحداث (المخطط 5):** `kind` = `Custom` (افتراضي، وكل حدث أقدم) | `Hit` | `Footstep` | `Sound` | `Vfx`؛ `data` كائن مسطّح نصي (أوامر `event.*` تقبل أرقامًا ومنطقيات وتخزنها نصًا). الحدود: ≤ 1024 حدثًا للمقطع، الاسم 1–200 محرف، ≤ 16 مدخلًا للحمولة، المفتاح 1–64 والقيمة ≤ 256 محرفًا، والزمن بين 0 و100,000 ث. `combat` اختياري (§11).
- `t` بوحدة flick (انظر ARCHITECTURE.md §5). الواجهة تعرضه كإطار: `frame = t * fps / 705600000`.
- لا تخزين لمفاتيح مخبوزة (baked) إلا عند الطلب. المقاطع المولّدة بالـAI تُحوَّل إلى مفاتيح مُختزلة قابلة للتحرير، مع حفظ الأصل الخام في `metadata/ai/`.

## 6. الهيكل العظمي (Rig) والوضعيات

**قواعد مهمة (المرحلة 2):**
- العظام مرتبة دائمًا: الأب قبل الابن. يُرفض الملف إذا خالف ذلك.
- الوضعية (`Pose`) تخزّن فقط العظام التي تغيّرت عن وضعية الراحة: `bones` تحويلات محلية (نسبة للأب)، و`controls` حالة المقابض.
- **مقابض IK للأيدي والأقدام** تُخزَّن في فضاء النموذج، فتبقى القدم المثبّتة في مكانها عندما يتحرك الجسم.
- **مقابض اتجاه الركبة والكوع (Pole)** تُخزَّن نسبةً لأول عظمة (الجذر)، فتتحرك مع الشخصية. الأوامر (`pose.set_control` و`pose.get`) تستقبل وتُرجع فضاء النموذج دائمًا.
- **حدود المفاصل:** إما زوايا Euler لكل محور، أو مفصل مفصلي `hinge` (محور + مدى + مخروط انحراف) للركبة والكوع، لأن زوايا Euler تنكسر بعد 90°.
- **الصيغة:** `Transform` في JSON: إذا غاب `scale` يُعتبر (1,1,1)، والدوران يُطبَّع، والحجم صفر مرفوض.

## 7. التصدير (Export) — المرحلة 4

الأمر `animation.export` (أداة MCP: `animation_export`) يكتب ملف `.glb` (glTF 2.0 ثنائي) وبجانبه ملف sidecar باسم `<name>.blazma.json`. الأمر `animation.validate` يعيد قراءة الملف ويقارنه بالمقطع.

### 7.1 الخبز (Baking)
- يُقيَّم المقطع إطارًا إطارًا من الإطار `startFrame` إلى `endFrame` **شاملًا الطرفين**، بالدالة نفسها التي يستخدمها التشغيل: من وضعية الراحة (وليس وضعية العمل)، مع إعادة حل سلاسل IK المثبّتة (Pinned) في كل إطار.
- **المدى الافتراضي:** من 0 إلى طول المقطع بالإطارات. إذا كان المقطع متكررًا (Loop) ونطاق التكرار جزءًا من المقطع فقط، فالافتراضي هو نطاق التكرار نفسه `[loopStart..loopEnd]`، فيتكرر الملف بلا قفزة. المدى الصريح يتقدم دائمًا.
- المقطع المتكرر يمر عبر `PlaybackTime`، فالإطار عند نهاية الـLoop يكرر وضعية بدايته كما في التشغيل، **لكن عظمة الـRoot motion تتقدم بإزاحة دورة كاملة** (موضعها عند نهاية الـLoop ناقص موضعها عند بدايته، في فضاء النموذج) عن كل دورة مكتملة، فالمشي المتكرر يستمر إلى الأمام ولا يقفز إلى الخلف.
- **حد التكلفة:** عدد الإطارات × عدد العظام ≤ 2,000,000 (و≤ 100,000 إطار) لكل تصدير، لكل المصادر (الواجهة والوكلاء)، وإلا `too_large`.
- الزمن في الملف: `(frame - startFrame) / fps` بالثواني، فأول إطار مُصدَّر هو الزمن 0.
- كل القنوات `LINEAR`، والـQuaternion متصل الإشارة بين الإطارات (لا قفز بين q و‎−q).
- **القنوات الثابتة:** القناة التي لا تتغير قيمتها تُكتب بمفتاحين فقط (أول إطار وآخر إطار) بدل مفتاح لكل إطار. اخترنا مفتاحين وليس واحدًا حتى تمتد كل قناة على طول المقطع كاملًا، فلا يستنتج أي محرك مدة خاطئة. يمكن تعطيل ذلك (`CompactConstantChannels = false`).

### 7.2 Root motion
- عظمة الـRoot motion: العظمة المربوطة بالاسم القياسي `root`، وإلا أول عظمة في الـRig.
- `rootMotion`: ‏`keep` (افتراضي، دون تغيير) أو `in_place` (حذف الحركة الأفقية X/Z نسبةً لأول إطار مُصدَّر مع إبقاء الارتفاع Y) أو `in_place_all` (حذف كل الإزاحة X/Y/Z).
- الاستخراج والحذف يتمان في **فضاء النموذج** (+Y للأعلى) حتى لو كان لعظمة الـRoot motion أب مُدار: تُحسب إزاحة العظمة في فضاء النموذج، ويُطرح الجزء المطلوب، ثم تُعاد العظمة إلى فضاء أبيها (الذي لا يتغير). ذلك قبل تحويلها إلى فضاء العقدة الأصلية في ملف الشخصية المستوردة.
- الإزاحة المحذوفة (أو القابلة للاستخراج في وضع `keep`) تُكتب في الـsidecar: فرق كل إطار عن السابق، والمجموع (`totalDisplacement`، ويشمل الدورات المتكررة)، وإزاحة دورة الـLoop الواحدة (`cycleDisplacement`، صفر لغير المتكرر).

### 7.3 الـMannequin المدمج
ملف جديد: عقدة لكل عظمة (بالترتيب نفسه، فرقم العقدة = رقم العظمة) بتحويل الراحة TRS، وتحت كل عظمة عقدة شبكة (Mesh) صلبة على شكل صندوق بطول المسافة إلى العظمة الابنة، مع Normals ومادة واحدة. لا يوجد Skin. القنوات تستهدف عقد العظام. `asset.generator = "Blazma Animation"`.

### 7.4 الشخصيات المستوردة
- يُستخدم ملف `.glb` الأصلي المضمَّن في المشروع (`assets/<id>/<file>`) **كما هو**: كل العقد والشبكات والـSkins والمواد والحركات الموجودة تبقى، وتُضاف حركتنا في آخر `animations`، وتُلحق بياناتها بنهاية الـBIN buffer. عند تكرار الاسم يُضاف لاحقة (`Walk_2`).
- القنوات تستهدف أرقام العقد الأصلية (`Rig.Source.NodeIndex`).
- **تحويل الجذر:** عند الاستيراد يُدمج تحويل العقد الأب غير العظمية (مثل عقدة `Z_UP`) في وضعية راحة عظمة الجذر. عند التصدير يُعاد تحويل قيمة الجذر إلى فضاء أبيها الحقيقي: `nodeLocal = inverse(World(parent)) * boneLocal` (دقيق عندما يكون مقياس الأب منتظمًا).
- العقدة المتحركة التي تستخدم `matrix` تُعاد كتابتها كـ`translation/rotation/scale` (لأن glTF يمنع تحريك عقدة لها matrix)، مع تحذير.
- **غير مدعوم (`unsupported_source`):** المصدر `.gltf`، أو ملف GLB يعتمد على buffers خارجية. (الاستيراد أصلًا يقبل `.glb` فقط للتضمين.) الـbuffers من نوع `data:` URI مقبولة.

### 7.5 الـSidecar ‏`<name>.blazma.json`
الإطارات فيه نسبية لأول إطار مُصدَّر، مثل أزمنة الـGLB.

```json
{
  "schema": "blazma.animation-export", "schemaVersion": 1, "generator": "Blazma Animation",
  "glb": "walk.glb", "animation": "Walk",
  "clip": { "id": "01J...", "name": "Walk" },
  "fps": { "numerator": 30, "denominator": 1 },
  "startFrame": 0, "endFrame": 25, "frameCount": 26, "durationSeconds": 0.8333,
  "loop": { "enabled": true, "startFrame": 0, "endFrame": 24, "clampedToExport": false },
  "markers": [ { "frame": 12, "name": "Pass", "kind": "contact" } ],
  "events": [ { "frame": 6, "time": 0.2, "name": "foot_contact_r", "kind": "footstep", "id": "01J...", "payload": { "surface": "stone" } } ],
  "rootMotion": { "mode": "in_place", "removed": true, "bone": "root", "axes": "xz",
                  "totalDisplacement": [0, 0, 0.6], "cycleDisplacement": [0, 0, 0.6],
                  "perFrameDelta": [[0,0,0], [0,0,0.004], "..."] },
  "bones": [ { "name": "thigh_l", "standard": "thigh_l", "parent": "pelvis", "node": 15 } ],
  "source": { "kind": "builtin", "rig": "Blazma Mannequin", "file": null, "project": "Demo" }
}
```

- `loop.endFrame` حصري (exclusive) مثل `duration`. نطاق التكرار يُقصّ إلى الإطارات المُصدَّرة (لا أرقام سالبة؛ `clampedToExport = true` عند القص)، ويكون `startFrame`/`endFrame` = `null` إذا لم يتقاطع مع المدى المُصدَّر.
- `markers[].kind`: ‏`marker` للعلامة العادية، أو اسم المرحلة (`initial`، `anticipation`، `main_action`، `contact`، `follow_through`، `recovery`، `final`).
- `bones[].standard`: الاسم القياسي من `humanoidMap` (أو `null`)، و`node` رقم العقدة في الـGLB.
- الحركة نفسها في الـGLB تحمل `extras.blazma` = ‏`{clipId, fps, startFrame, endFrame, rootMotion}`، ويستخدمه `animation.validate` لمعرفة خيارات التصدير.

### 7.5.1 بيانات القتال في الـSidecar — المرحلة 9
تُضاف إلى الـsidecar (إضافة متوافقة؛ `schemaVersion` يبقى 1 والمستهلك يتجاهل الحقول غير المعروفة) عندما يكون للمقطع أو للشخصية المُصدَّرة بيانات قتال أو يدخل المقطع في Combo:

```json

  "phases": { "startup": { "startFrame": 0, "endFrame": 10 }, "active": { "startFrame": 10, "endFrame": 18 },
              "recovery": { "startFrame": 18, "endFrame": 36 } },
  "hitboxes": [ { "id": "01J...", "name": "Blade",
                  "shape": { "kind": "capsule", "radius": 0.05, "length": 0.8, "size": null },

                                  "offset": { "translation": [0,0,0], "rotation": [0,0,0,1] } },

                  "damage": 20, "knockback": 0.4, "hitstopFrames": 4, "tags": ["slash"] } ],

                   "clip": null, "clipId": null, "durationSeconds": 0.6 } ],
```

- كل الإطارات نسبية لأول إطار مُصدَّر و`endFrame` حصري، ما عدا `combos[].attacks[]` فهي بإطارات مقطع الضربة نفسه. نطاقات المراحل والـHitboxes تُقص إلى الإطارات المُصدَّرة، والـHitbox الذي لا يكون نشطًا في أي إطار مُصدَّر لا يُكتب.
- `shape.kind`: `sphere` (نصف القطر) | `capsule` (مركزا الكرتين على بعد `length` على المحور Y المحلي، متمركزة على الأصل) | `box` (`size` الأبعاد الكاملة). `offset` في إطار العظمة (أو الجسم، دون مقياسه).
- `attachment.node` = رقم عقدة العظمة في الـGLB (كما في `bones[].node`) أو عقدة الجسم (كما في `props[].node`)؛ `null` لجسم لم يُصدَّر.
- `hurtboxes` و`reactions` للشخصية المُصدَّرة (`characterId`، افتراضيًا أول شخصية بالـRig).
- **التحقق (`SidecarValidator`)** يعمل بعد التصدير وفي `animation.validate` (إن وُجد الملف بجانب الـGLB، ≤ 64 MB): الإطارات داخل المدى والأحداث مرتبة وأنواعها معروفة، عقدة كل Hitbox/Hurtbox هي عقدة عظمته (أو جسمه) في الـsidecar نفسه، النطاقات مرتبة وغير فارغة، وHitboxes الـsidecar هي بالضبط Hitboxes المقطع النشطة في المدى، وعدد الـHurtboxes مطابق للشخصية. يُقرأ كإدخال غير موثوق (تنقّل بفحص الأنواع، حلقات محدودة ≤ 100,000 عنصر، بلا عَوْد) وكل خلل يصبح Issue.

### 7.6 التحقق (`animation.validate`)
يعيد قراءة الملف ويفحص: رأس GLB (magic/version/length) ومحاذاة الـchunks على 4 بايت، حدود الـbufferViews والـaccessors، وجود min/max لـ`POSITION` ولأزمنة الحركة ومطابقتها، صحة الهرمية (أب واحد، بلا دورات)، مدة الحركة (± نصف إطار)، ثم:
1. يقارن كل قناة لكل عظمة في كل إطار مع خبز المقطع (بعد التصدير مباشرةً يُعاد استخدام الخبز نفسه ولا يُخبز مرة ثانية؛ `validate=false` يتخطى التحقق). السماحيات: الموضع ‎1e-4 م، الدوران ‎0.01°، المقياس ‎1e-4.
2. **فحص مستقل** (لا يعتمد على الخبز ولا على ربط العظام بالعقد): يحسب مواضع ودورانات المفاصل في فضاء المشهد بـFK عبر هرمية عقد **الملف نفسه** (بما فيها الآباء غير العظمية للشخصية المستوردة) ويقارنها بتقييم التطبيق `RigEvaluator.Model(ClipEvaluator.Evaluate(...))`، بعد تطبيق الـRoot motion المعلن (دورات الـLoop، والحذف في `in_place`) على عظمة الـRoot motion وأبنائها. السماحيات: ‎5e-4 م و‎0.05°، على 240 إطارًا كحد أقصى موزعة بالتساوي.
للشخصية المستوردة يتحقق أيضًا من أن عدد العقد والهرمية والشبكات والـSkins مطابق للملف الأصلي. الملف التالف لا يرمي استثناءً أبدًا: كل خطأ (accessor خارج الحدود أو بعدد ضخم — يُفحص قبل حجز الذاكرة —، نوع مخرجات خاطئ لمسار الحركة، قيم `null` في TRS…) يصبح Issue.

### 7.7 قواعد الوكلاء
`animation.export` لا يغيّر المشروع (Effect = ReadOnly، لا يدخل سجل التراجع)، لكنه يعلن مسار الكتابة (`CommandDescriptor.FileArg`)، فيطبّق `AgentHost` عليه: امتداد `.glb` إلزامي، اسم ملف صالح على كل الأنظمة (لا `:` ولا محارف `<>"|?*` أو تحكم ولا نقطة/مسافة في النهاية، وإلا `invalid_path`)، المجلد الأب موجود، **ملف جديد فقط** (`file_exists` حتى مع `overwrite=true`، فالخيار يُفرض `false` للوكلاء ويحمي الـsidecar أيضًا)، ولا يُكتب فوق ملف المشروع، والمسار — بعد حل الروابط الرمزية في **كل** مكوّن منه — داخل **مجلدات الكتابة** (مجلد المشروع المفتوح و`AllowedWriteRoots`؛ مجلدات القراءة لا تمنح الكتابة)، وإلا `approval_required` (مستخدم حاضر في الوضع Assisted) أو `path_not_allowed`. يمرّر `AgentHost` إلى الأمر المسار الحقيقي الذي فحصه، والأمر يعيد حل المجلد قبل الكتابة مباشرةً (`path_changed` إن تغيّر)، ويكتب دون استبدال ذريًا (`file_exists` إن ظهر الملف أثناء الخبز). عند الموافقة على طلب معلّق يُعاد الفحص، ويُرفض (`path_changed`) إن صار المسار يشير إلى مكان آخر. إذا فشلت كتابة الـsidecar يُحذف الـGLB الذي أنشأه التصدير نفسه. الواجهة وحدها تستطيع الاستبدال بـ`overwrite=true`. `animation.validate` يخضع لقواعد القراءة (مجلدات القراءة والكتابة ومجلد المشروع).

### 7.8 الأجسام (Props) في التصدير — المرحلة 8
- يُصدَّر كل جسم مربوط بعظمة من عظام الشخصية المُصدَّرة، وكل جسم له مسارات في المقطع (`PropEvaluator.PropsFor`)، إلا مع `IncludeProps = false`.
- الجسم المربوط يتبع **شخصيته فقط**: شخصيتان على Rig واحد (مثل نسختين من الـMannequin) لا تتشاركان الجسم؛ التصدير والتحقق بـ`characterId` (الافتراضي: أول شخصية تستخدم الـRig).
- لكل جسم عقدة باسمه وعليها `extras.blazma = {kind: "prop", propId}` وقنوات `translation`/`rotation`/`scale` (LINEAR، بالقواعد نفسها في 7.1). المربوط ابنٌ لعقدة عظمته (القيمة المحلية = الإزاحة المتحركة)، والحر جذرٌ في المشهد (القيمة = التحويل العالمي). الجسم المربوط بشخصية أخرى يُصدَّر حرًّا بتحويله الحر مع تحذير.
- الشكل تحت العقدة كابن ثابت: صندوق/كرة/أسطوانة مولّدة (وحدة مركزها الأصل، مقاسة بـ`size`) بمادة `BlazmaProp`، أو المشهد الافتراضي لملف الـ`.glb` المضمَّن (تُنسخ الشبكات والـaccessors والمواد والقوام والصور؛ تُحذف الـSkins والكاميرات وأوزان morph والحركات وسمات `JOINTS_n`/`WEIGHTS_n`؛ الملف الذي يتطلب امتدادات `extensionsRequired` يُرفض).
- **حدود نسخ ملف الجسم** (عند `prop.import` وأيضًا عند التصدير، لأن الأرشيف قد يحمل أي بايتات): ≤ 10,000 عقدة في الملف و≤ 256 مستوى عمق؛ العقدة التي يُوصل إليها مرتين (دورة أو أبوان) تُرفض؛ تُمشى الشجرة بمكدس صريح (بلا عَوْد). النطاق المستخدم من كل buffer يُنسخ مرة واحدة وتُعاد قواعد الـbufferViews إليه، فالبايتات المنسوخة لا تتجاوز الـbuffers المصدر مهما تداخلت الـviews. كل كائن `extensions` يُحذف (مع تحذير بأسمائها) فلا يُستعمل امتداد غير معلن في `extensionsUsed`؛ الصورة الخارجية (`uri` غير `data:`) أو بلا بيانات تُحذف مع القوام وخانات المواد التي تستخدمها (تحذير). أي خلل → `invalid_gltf` (الاستيراد يرفض؛ التصدير يضع صندوقًا مع تحذير).
- `POSITION` min/max للنموذج المستورد يجب أن تكون أرقامًا منتهية ضمن ±10,000 م والامتداد ≤ 10,000 م، وإلا يُرفض الاستيراد (`invalid_gltf`).
- للشخصية المستوردة: عقد الجسم وشبكاته وموادّه تُلحق بعد عناصر الملف الأصلي، فيبقى كل ما في الأصل بأرقامه.
- الحركة تحمل `extras.blazma.props` = عدد الأجسام (يُكتب فقط إن وُجد جسم)، والـsidecar قائمة `props: [{id, name, shape, node, attachedTo}]`.
- التحقق (`ExportValidator`): كل جسم متوقع موجود مرة واحدة تحت الأب الصحيح وله القنوات الثلاث، وفحص مستقل لتحويله العالمي (FK عبر عقد الملف) مقابل `PropEvaluator.World` بسماحية 5e-4 م و0.05°، مع إزاحة الـRoot motion للمربوط تحت عظمة الجذر. للشخصية المستوردة يُقبل وجود عقد/شبكات/مواد زائدة بشرط أن تكون جزءًا من جسم، ويبقى عدد الـSkins مطابقًا.

## 8. تسلسلات المقاطع (Sequence) — المخطط 4

```json
{ "id": "01J...", "name": "Walk to run", "character": "01J...", "fps": { "num": 30, "den": 1 },
  "alignRoot": true, "alignYaw": true,
  "items": [ { "id": "01J...", "clip": "01J...", "startFrame": 0, "inFrame": 0, "outFrame": null,
               "speed": 1, "loops": 2, "blendInFrames": 0, "blendCurve": "Smooth" },
             { "id": "01J...", "clip": "01J...", "startFrame": 120, "inFrame": 15, "speed": 1, "loops": 2,
               "blendInFrames": 10, "blendCurve": "Smooth" } ] }
```

- `startFrame` و`blendInFrames` بإطارات التسلسل (`fps`)؛ `inFrame`/`outFrame` بإطارات المقطع نفسه، و`outFrame` حصري (`null` = نهاية الـLoop للمقطع المتكرر، وإلا طوله). `blendCurve`: `Linear` | `Smooth` | `EaseIn` | `EaseOut`.
- **الحدود** (هي نفسها في الأوامر وعند التحميل، فلا يصل مشروع عبر الأوامر إلى حالة لا تُحفظ): ≤ 256 عنصرًا في التسلسل؛ `startFrame`/`inFrame`/`outFrame`/`blendInFrames` بين 0 و10,000,000؛ `loops` 1–1000؛ `speed` 0.01–10؛ `fps` موجب ≤ 1000 (الوسيط `fps` في `sequence.create` ≤ 240)؛ معرّفات العناصر والتسلسلات فريدة. في التقييم: ≤ 8 عناصر تُدمج في وقت واحد (الأمر يرفض `too_many_blends`، والملف الأقدم يُتخطى الزائد بتحذير)، وميزانية عمل للتحضير (مجموع إطارات الدمج × العناصر × العظام ≤ 2e7) وللخبز (≤ 4e7) وإلا `too_large`.
- العناصر مرتبة بـ`startFrame`. العنصر الذي يشير إلى مقطع محذوف أو إلى Rig آخر يُتخطى بتحذير (الحذف مسموح)، لكن القيم خارج الحدود أعلاه أو `outFrame ≤ inFrame` أو عنصر فارغ ترفض الملف (`invalid_json`) مع اسم التسلسل ومعرّف العنصر.
- التقييم والدمج والمحاذاة: ARCHITECTURE.md §8.3. التصدير = `sequence.bake` (مقطع عادي) ثم `animation.export`.

## 9. الأجسام (Props) — المخطط 4

```json
{ "id": "01J...", "name": "Sword", "shape": "Box", "size": [0.04, 0.9, 0.04], "asset": "",
  "transform": { "t": [0,0,0], "r": [0,0,0,1] },
  "attachment": { "character": "01J...", "bone": "01J...", "offset": { "t": [-0.08,0.35,0], "r": [0,0,0,1] } } }
```

- `shape`: `Box` (الأبعاد الكاملة)، `Sphere` (القطر)، `Cylinder` (القطر × الطول على Y)، أو `Mesh` مع `asset` = ملف `.glb` مضمَّن في `assets/<id>/` (يُرفض الملف إن غاب الأصل). `size`: كل مكوّن > 0 و≤ 10,000 م (يُفحص كل مكوّن على حدة؛ لا طول متجه قد يفيض). معرّفات الأجسام فريدة. الخطأ يسمّي الجسم ومعرّفه.

- حذف جسم يُبقي مساراته في المقاطع (تُتجاهل)، ويُزال ملفه المضمَّن إن لم يعد مستخدمًا.
