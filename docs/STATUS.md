## بعد v0.11.0 — صقل الفيزياء (D46)
- طلب: «حسّن فيزياء الحركة» — وزن وزخم وتلامس ثابت مع الأرض وسقوط وقفز طبيعيان.
- `motion.physics_polish` جديد ويعمل افتراضيًا بعد التوليد وتطبيق القوالب (`physicsPolish=false` لإيقافه): أقدام ثابتة، لا اختراق للأرض، طيران باليستي، انتقالات بلا قفزات زخم، سقوط متسارع مع ارتداد، حركة ثانوية، توازن (ARCHITECTURE 7.8).
- مقطع Kimodo للبطل: انزلاق القدم 37.8 ← 6.9 سم، أدنى نقطة −162 ← 0 مم، الاستلقاء على الأرض (−94 ← 0.4 مم). الحركة المخطَّطة: انزلاق 29.7 ← 0.5 سم، قفزة سرعة الجذر عند الحدود 2.34 ← 0.94 م/ث. الرسم: `docs/screenshots/physics-before-after.png`.
- القفز والسقوط والجري الإجرائية أُعيدت بقواعد فيزيائية (القفز: القطع المكافئ 3.5 ← 0.1 سم، أقصى تسارع 144 ← 28 م/ث²).
- **غير متحقق منه**: الصقل على مقاطع Kimodo أخرى غير مقطع البطل، والمعاينة في Godot.

## بعد v0.11.0 — مخطِّط وصف الحركة (D45)
- شكوى: «أكتب في واحد وراك اجري وبعدها موت فيموت فورًا دون أن يجري». السبب: Kimodo يولّد حركة واحدة لكل وصف ويفهم الإنجليزية، والإجرائي يطابق كلمة واحدة.
- الحل: `MotionPromptPlanner` يقسّم الوصف إلى خطوات (التفات مفزوع ← جري ← موت) ويترجمها دون اتصال ويوزّع المدة؛ كل خطوة تُولَّد وحدها وتُدمج بآلية التسلسلات في مسودة واحدة بعلامة لكل خطوة. `motion.plan_prompt` جديد، و`motion.generate` يقبل `segments`. نافذة التوليد تعرض الخطوات أثناء الكتابة مع التعديل.
- الإجرائي (ليس ذكاءً اصطناعيًا): التفات للخلف، استدارة، سقوط/موت ينتهي مستلقيًا، توقف، لكمة — بأقدام ثابتة دون انزلاق.
- **غير متحقق منه**: جودة الدمج بالنموذج الحقيقي (Kimodo) — اختُبر بالمولّد الإجرائي والـrunner المزيّف فقط.

## 1.0.0 — CUDA تنزيل اختياري (D47)
- المثبّت والـzip بلا واجهة CUDA (المتوقع نحو 150 MB للمثبّت بدل 460): `ggml-cuda` ومكتبات CUDA 12.4 ملف إصدار منفصل `blazma-cuda-backend-<v>-win-x64.zip` (نحو 550 MB)، وقيم التحقق في `tools/kimodo/cuda-backend.json`.
- الإعدادات ← AI: قسم «تسريع بطاقة الرسومات (CUDA)» يظهر مع بطاقة NVIDIA فقط، زر تنزيل بضغطة المستخدم فقط مع تقدم وإلغاء واستئناف، تحقق SHA-256 للأرشيف ولكل ملف، إزالة. Auto يلتقطه عبر `GGML_BACKEND_PATH` دون إعادة بناء الـrunner، و«وُلِّدت على» يلمّح للتنزيل حين جرى التوليد على NVIDIA عبر Vulkan.
- متحقق: اختبارات النواة (خادم محلي: تنزيل، تحويل، استئناف، بصمة خاطئة، أرشيف لا يطابق القائمة، إزالة، حالة، بيئة الـrunner)، واختبار الواجهة `p12-*-cuda-*` بالعربية والإنجليزية، ومنطق تقسيم `build-release.sh` على ملفات وهمية.
- **غير متحقق منه**: بناء إصدار كامل بالـrunner الحقيقي، والتحميل الفعلي لـ`ggml-cuda.dll` من `GGML_BACKEND_PATH` على Windows مع بطاقة NVIDIA (الكود في GGML المثبّت يدعمه، ومكتبات CUDA تُوجد عبر `PATH`)، والتنزيل الحقيقي من GitHub.

## v0.11.0 — Kimodo على بطاقة الرسوميات (D44)
- `kimodo-runner` 0.3.0: runner واحد بواجهات GGML خلفية تُحمَّل وقت التشغيل (CPU بكل مستويات التعليمات، Vulkan، CUDA 12.4 مع DLLاتها) وأوضاع **تلقائي (البطاقة أولًا)** / **البطاقة فقط** / **المعالج فقط** / **البطاقة + المعالج**، مع انتقال تلقائي CUDA ← Vulkan ← بطاقة+معالج ← معالج وتحذير يقول ما حدث، و«وُلِّدت على: …» بعد كل توليد.
- بناء Vulkan على Windows أُصلح (SPIRV-Headers مثبّتة بالـcommit). الإعداد `cpu` الذي كان المثبّت يضعه خطأً يعود «تلقائي» مرة واحدة.
- CI: تشغيل `kimodo-runner` رقم 42365146397 نجح (Windows CPU+Vulkan، Windows CUDA 12.4 — بناؤه نحو ساعتين، Linux CPU+Vulkan)، والإصدار بُني من تشغيل Release رقم 42387662088 واجتاز فحص الدخان: <https://github.com/mr-kateba/blazma-Animation/releases/tag/v0.11.0>.
- **غير متحقق منه**: التشغيل على بطاقة حقيقية (CUDA وVulkan) — أجهزة CI بلا بطاقة رسوميات؛ تحقق CI من تحميل المكتبات وعمل المعالج فقط. يجب أن يجرّبه المستخدم: الإعدادات ← AI ← «فحص» يسرد الأجهزة، ثم توليد يُظهر الجهاز المستخدم.
