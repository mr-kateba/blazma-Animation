## بعد v0.11.0 — مخطِّط وصف الحركة (D45)
- شكوى: «أكتب في واحد وراك اجري وبعدها موت فيموت فورًا دون أن يجري». السبب: Kimodo يولّد حركة واحدة لكل وصف ويفهم الإنجليزية، والإجرائي يطابق كلمة واحدة.
- الحل: `MotionPromptPlanner` يقسّم الوصف إلى خطوات (التفات مفزوع ← جري ← موت) ويترجمها دون اتصال ويوزّع المدة؛ كل خطوة تُولَّد وحدها وتُدمج بآلية التسلسلات في مسودة واحدة بعلامة لكل خطوة. `motion.plan_prompt` جديد، و`motion.generate` يقبل `segments`. نافذة التوليد تعرض الخطوات أثناء الكتابة مع التعديل.
- الإجرائي (ليس ذكاءً اصطناعيًا): التفات للخلف، استدارة، سقوط/موت ينتهي مستلقيًا، توقف، لكمة — بأقدام ثابتة دون انزلاق.
- **غير متحقق منه**: جودة الدمج بالنموذج الحقيقي (Kimodo) — اختُبر بالمولّد الإجرائي والـrunner المزيّف فقط.

## v0.11.0 — Kimodo على بطاقة الرسوميات (D44)
- `kimodo-runner` 0.3.0: runner واحد بواجهات GGML خلفية تُحمَّل وقت التشغيل (CPU بكل مستويات التعليمات، Vulkan، CUDA 12.4 مع DLLاتها) وأوضاع **تلقائي (البطاقة أولًا)** / **البطاقة فقط** / **المعالج فقط** / **البطاقة + المعالج**، مع انتقال تلقائي CUDA ← Vulkan ← بطاقة+معالج ← معالج وتحذير يقول ما حدث، و«وُلِّدت على: …» بعد كل توليد.
- بناء Vulkan على Windows أُصلح (SPIRV-Headers مثبّتة بالـcommit). الإعداد `cpu` الذي كان المثبّت يضعه خطأً يعود «تلقائي» مرة واحدة.
- CI: تشغيل `kimodo-runner` رقم 42365146397 نجح (Windows CPU+Vulkan، Windows CUDA 12.4 — بناؤه نحو ساعتين، Linux CPU+Vulkan)، والإصدار بُني من تشغيل Release رقم 42387662088 واجتاز فحص الدخان: <https://github.com/mr-kateba/blazma-Animation/releases/tag/v0.11.0>.
- **غير متحقق منه**: التشغيل على بطاقة حقيقية (CUDA وVulkan) — أجهزة CI بلا بطاقة رسوميات؛ تحقق CI من تحميل المكتبات وعمل المعالج فقط. يجب أن يجرّبه المستخدم: الإعدادات ← AI ← «فحص» يسرد الأجهزة، ثم توليد يُظهر الجهاز المستخدم.
